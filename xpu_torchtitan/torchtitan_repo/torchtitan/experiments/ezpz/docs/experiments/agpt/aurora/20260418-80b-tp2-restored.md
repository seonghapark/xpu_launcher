> Sam Foreman

## Overview

The agpt 80B model at TP=2 is **working again** on Aurora. This config had been
broken since ~2026-04-12 with OOM on step 2 (missed by 60 MiB). The fix was
the removal of `import intel_extension_for_pytorch` (IPEX), not a framework
upgrade — this run still uses `torch==2.10` from `aurora_frameworks-2025.3.1`.

Memory and throughput are **identical** to the April 4 benchmark (59.82 GiB,

not in the model or parallelism code.

## Root Cause

The fix was the **removal of `import intel_extension_for_pytorch`** (IPEX).
This run still uses `torch==2.10` from `aurora_frameworks-2025.3.1` — there
was no framework upgrade.

IPEX was being imported unconditionally and registered XPU allocator hooks
that increased per-rank memory overhead by ~60 MiB. At 93.49% memory
utilization, that 60 MiB was exactly the margin between fitting and OOM.

The fact that memory is exactly 59.82 GiB (93.49%) — identical to the
April 4 run and the Sunspot benchmark — confirms the allocator is behaving
normally again without IPEX interference.
