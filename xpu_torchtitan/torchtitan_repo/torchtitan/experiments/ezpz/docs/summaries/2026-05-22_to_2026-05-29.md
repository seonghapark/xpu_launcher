### `pytorch/torchtitan` PR — `histc → bincount`/`scatter_add_` for MoE routing

https://github.com/pytorch/torchtitan/pull/3436 — filed 2026-05-27,
open. The story:

1. Discovered https://github.com/pytorch/torchtitan/pull/3146's
   merged diff was missing the `histc → bincount` swap its commit
   message described. Only the `aten.topk.default` SAC save-list
   change actually landed; the `histc` calls at
   `common/moe.py:262` and `common/token_dispatcher.py:92` were
   untouched. Verified via GitHub API + an XPU smoke that
   `--debug.deterministic` on MoE+XPU still fails with the same
   `_histc_xpu does not have a deterministic implementation` error
   from 2026-05-21.
2. Filed PR 3436 with the bincount swap + a `test_moe_routing.py`
   that #3146 also referenced but never landed. Verified locally
   that bincount unblocks `--debug.deterministic` on Sunspot 2N
   (alloc 12467457, byte-identical loss step 50 = 6.17087 across
   two deterministic runs).
3. Reviewer (@tianyu-l) pointed at the prior #3146 conversation
   where @songhappy benchmarked bincount as **−20% slower on XPU**
   and dropped the swap deliberately.
4. Re-measured: bincount is **+117.6% slower per kernel** in a
   microbench
   ([`verify_scatter_reduce_xpu_determinism.py`](../upstream-issues/verify_scatter_reduce_xpu_determinism.py)),
   confirming songhappy. **But** `torch.scatter_add_` is +0.5%
   (noise) and is also deterministic. Proposed scatter as the
   cleaner default.
5. Followed up with a properly-powered statistical E2E A/B on a
   single alloc (12467486, 6 trials in strict alternation H/B/H/B/H/B,
   135 per-step samples per variant): Welch's t-test **p=0.66, fail
   to reject H₀** — no detectable E2E perf difference between histc
   and bincount on `moe_2b_ep` despite the per-kernel cost. Driver
   + analyzer at
   [`stats_histc_vs_bincount_run_trials.sh`](../upstream-issues/stats_histc_vs_bincount_run_trials.sh) /
   [`stats_histc_vs_bincount_analyze.py`](../upstream-issues/stats_histc_vs_bincount_analyze.py).
6. @tianyu-l then pointed at https://github.com/pytorch/torchtitan/pull/3450
   — a draft PR by @acisseJZhong that builds a boolean
   `routing_map_BLE` via scatter in the router and replaces **both**
   histc call sites with `routing_map.sum(...)`, reused across the
   router and the dispatcher. Strictly better than #3436. PR #3436
   left open in case #3450 stalls in draft; nothing else to do on
   our side.
