## High-Level

Over ~2 weeks and **291 commits**, we built a comprehensive training optimization research platform on Intel XPU (Sunspot), going from basic benchmarking to a systematic optimizer/architecture competition with live experiment tracking.

**Three major arcs:**

1. **Benchmarking & Infrastructure (2026-04-12 → 2026-04-18):** Built LR finder, scaling study tooling, and benchmark scripts across 3 ALCF machines. Established baselines for agpt_2b/20b/80b and MoE models. Fixed critical XPU bugs (XCCL barriers, 80B TP=2 OOM). Merged upstream fused QKV, token dispatcher, and expert parallelism.

2. **Production Readiness (2026-04-18 → 2026-04-25):** Created production training scripts, set up torch 2.13 venv (+23% throughput), ran 2B weak scaling study (2–64 nodes, 94% efficiency at 64N), and started production training runs with checkpointing and W&B tracking.

3. **Optimizer Competition (2026-04-26 → 2026-04-27):** Launched a systematic optimizer/architecture competition. Implemented 3 new optimizers (Mano, SPAM, TorchMuon), 3 architecture tweaks (QK-Norm, logit softcapping, ReLU²), and ran 40+ experiments across 4 rounds. Built generic HF dataset streaming, local dataset caching, and live loss curve plotting.

#### New Optimizers (2026-04-26)

- **Mano** ([`optimizer/mano.py`](https://github.com/saforem2/torchtitan/blob/ezpz/torchtitan/experiments/ezpz/optimizer/mano.py)) — manifold-normalized, vector-norm ops instead of Newton-Schulz. Runs at AdamW speed (~7,200 TPS) vs Muon's 4,700. Based on [arxiv 2601.23000](https://arxiv.org/abs/2601.23000). Commit: [`03af1057`](https://github.com/saforem2/torchtitan/commit/03af1057)
- **SPAM** ([`optimizer/spam.py`](https://github.com/saforem2/torchtitan/blob/ezpz/torchtitan/experiments/ezpz/optimizer/spam.py)) — spike-aware gradient clipping + periodic momentum reset. Based on [arxiv 2501.06842](https://arxiv.org/abs/2501.06842). Commit: [`03af1057`](https://github.com/saforem2/torchtitan/commit/03af1057)
- **TorchMuon** — `_CompositeOptimizer` wrapper for [`torch.optim.Muon`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Muon.html) (built-in since PyTorch 2.9). Confirmed same speed as custom Muon on XPU — Newton-Schulz overhead is algorithmic, not implementation. Commit: [`a382213e`](https://github.com/saforem2/torchtitan/commit/a382213e)

#### Architecture Tweaks (2026-04-26 → 2026-04-27)

- **QK-Norm** — RMSNorm on Q,K before attention. New `2B_qknorm` variant. Commit: [`e6e666cb`](https://github.com/saforem2/torchtitan/commit/e6e666cb)
- **Logit Softcapping** — FlexAttention `score_mod` with tanh cap at 30.0. Falls back to eager on XPU (4x slower — Triton-XPU can't codegen `tanh`). Commit: [`01b88cfe`](https://github.com/saforem2/torchtitan/commit/01b88cfe), fix: [`9d9e7529`](https://github.com/saforem2/torchtitan/commit/9d9e7529)
- **ReLU²** — Subclassed FeedForward with `relu(x)²`. Didn't help (3.92 vs 3.80 baseline). Commit: [`01b88cfe`](https://github.com/saforem2/torchtitan/commit/01b88cfe)
- **WSM** — Checkpoint merging utility ([`eval/merge_checkpoints.py`](https://github.com/saforem2/torchtitan/blob/ezpz/torchtitan/experiments/ezpz/eval/merge_checkpoints.py)). Commit: [`01b88cfe`](https://github.com/saforem2/torchtitan/commit/01b88cfe)

## Key Discoveries

- **Muon's 35% speed penalty** is inherent to Newton-Schulz on XPU, not fixable by implementation — confirmed by [`torch.optim.Muon`](https://docs.pytorch.org/docs/stable/generated/torch.optim.Muon.html) matching custom Muon TPS. Commit: [`a382213e`](https://github.com/saforem2/torchtitan/commit/a382213e)
- **QK-Norm helps massively in short runs** (+0.23) but washes out at 10B (+0.009). Revives in round 4 decay phase (+0.015)
- **Rankings flip** between short/long training: Muon/Mano win speedruns, AdamW wins in cosine decay phase at scale
- **FlexAttention on XPU** falls back to eager (4x slower) — `Torchinductor does not support code generation for complex operators`
- **HF streaming data shuffle** causes ~1.3 loss variance between runs — commit: [`16aa4d46`](https://github.com/saforem2/torchtitan/commit/16aa4d46)
- **sqrt LR scaling rule too aggressive** — AdamW at 3.7e-3 diverged (confirmed in round 4)
- **ReLU² hurts** this architecture (3.92 vs 3.80 baseline)
- **Local dataset loader + softcap** has a data sharding bug causing memorization at small GBS
